# AI Support Bot — бот поддержки клиентов по вашей базе знаний

**Боль.** В клинике, автосервисе или интернет-магазине до 70 % сообщений в мессенджере — это одни и те же
вопросы: «сколько стоит», «как записаться», «какие сроки», «можно вернуть». Администратор отвечает на них
по десять раз в день, вечером и в выходные никто не отвечает, а клиент уходит туда, где ответили быстрее.

**Решение.** Бот отвечает на такие вопросы сам — **строго по вашим документам и с указанием источника**.
Если ответа в базе нет, он не выдумывает его, а передаёт вопрос живому оператору вместе с готовым тикетом.
Спорные и эмоциональные обращения («верните деньги», «пожалуюсь», «позовите оператора») уходят человеку
сразу, без попытки «успокоить» клиента шаблоном.

**Что важно для вас как для заказчика:**

* работает **без интернета, без API-ключей и без единой сторонней библиотеки** — только стандартный Python;
* вы управляете знаниями: база — это обычные markdown-файлы в папке `kb/`, их можно править без программиста;
* каждое обращение к оператору фиксируется, а команда `stats` показывает, что бот не смог ответить —
  то есть вы видите, какие страницы базы знаний надо дописать;
* в репозитории три демонстрационных бизнеса (автосервис, стоматология, интернет-магазин) с реальными
  ценами и регламентами, чтобы вы могли пощупать поведение за 30 секунд.

## Демо за 30 секунд

Нужен только Python 3.10+ (проверялось на 3.12). Никаких `pip install` — зависимостей нет.

```bash
git clone <адрес-репозитория> ai-support-bot
cd ai-support-bot
python -m ai_support_bot chat
```

Вы попадёте в консольный чат, который работает **офлайн**: тот же самый код, что и в Telegram-боте, но без
токена. Доступные команды внутри чата: `/kb <направление>` (переключить базу знаний), `/stats`, `/tickets`,
`/help`, `/exit`.

Разовый вопрос без входа в диалог (удобно для проверки и для скриптов):

```bash
python -m ai_support_bot chat --ask "Сколько стоит замена масла в двигателе?"
```

Полный набор команд:

| Команда | Что делает |
|---|---|
| `python -m ai_support_bot chat` | офлайн-чат в консоли — главное демо, токен не нужен |
| `python -m ai_support_bot chat --ask "вопрос"` | задать один вопрос и выйти (можно указать несколько раз) |
| `python -m ai_support_bot ingest` | пересобрать поисковый индекс по папке `kb/` |
| `python -m ai_support_bot stats` | аналитика по журналу диалогов |
| `python -m ai_support_bot serve` | настоящий Telegram-бот (нужен токен) |

Что происходит при сборке индекса (эта команда нужна после правки базы знаний; обычно её вызывает
чат автоматически, если файлы изменились):

```text
$ python -m ai_support_bot ingest
Индексирую базу знаний: ai_support_bot/kb
  avtoservice      файлов: 5, фрагментов: 20
  shop             файлов: 5, фрагментов: 20
  stomatologiya    файлов: 5, фрагментов: 20
Всего: 15 файлов, 60 фрагментов, словарь: 1101 терминов
Индекс сохранён: data/index.json
Проверить поиск: python -m ai_support_bot chat --ask "Сколько стоит замена масла?"
```

## Как подключить настоящую LLM

Бот умеет отвечать двумя способами:

* **`echo`** — офлайн-режим по умолчанию: ответ собирается из найденных фрагментов базы знаний через
  русские шаблоны. Ничего не выдумывает и работает без интернета — именно его видит проверяющий;
* **`openai`** — любой OpenAI-совместимый API: OpenAI, DeepSeek, OpenRouter, локальная Ollama. Модель
  получает тот же вопрос и те же фрагменты базы знаний плюс жёсткие правила в системном промпте.

Режим выбирается автоматически: если заданы `LLM_BASE_URL` и `LLM_MODEL`, используется `openai`,
иначе — `echo`. Явно: `--provider echo` или `--provider openai`.

| Переменная | Обязательна | Назначение | Пример |
|---|---|---|---|
| `LLM_BASE_URL` | да, для реальной LLM | адрес OpenAI-совместимого API | `https://api.deepseek.com/v1` |
| `LLM_API_KEY` | зависит от провайдера | ключ доступа (для Ollama не нужен) | `sk-...` |
| `LLM_MODEL` | да, для реальной LLM | имя модели | `deepseek-chat` |
| `TELEGRAM_BOT_TOKEN` | да, для `serve` | токен бота от @BotFather | `123456:AA...` |
| `OPERATOR_CHAT_ID` | нет | чат оператора, куда пересылать обращения | `123456789` |
| `TELEGRAM_POLL_TIMEOUT` | нет | таймаут длинного опроса, секунды | `25` |
| `TELEGRAM_API_BASE` | нет | свой адрес Bot API (прокси, локальный сервер) | `https://api.telegram.org` |

Примеры для популярных провайдеров (Windows PowerShell / Linux):

```powershell
# DeepSeek
$env:LLM_BASE_URL="https://api.deepseek.com/v1"; $env:LLM_MODEL="deepseek-chat"; $env:LLM_API_KEY="sk-..."
python -m ai_support_bot chat
```

```bash
# OpenRouter
export LLM_BASE_URL="https://openrouter.ai/api/v1"
export LLM_MODEL="qwen/qwen-2.5-72b-instruct"
export LLM_API_KEY="sk-or-..."
python -m ai_support_bot serve

# Локальная Ollama (ключ не нужен, интернет не нужен)
export LLM_BASE_URL="http://localhost:11434/v1"
export LLM_MODEL="llama3.1"
python -m ai_support_bot chat
```

Если LLM-эндпоинт недоступен, бот **не оставит клиента без ответа**: он откатится на офлайн-сборку из
базы знаний, а в тексте ответа появится пометка о причине (`провайдер echo-fallback`).

## Настоящий Telegram-бот

1. Создайте бота у [@BotFather](https://t.me/BotFather): команда `/newbot`, скопируйте токен.
2. Напишите своему боту любое сообщение и узнайте свой `chat_id` (например, через @userinfobot) — это
   будет чат оператора.
3. Запустите:

```powershell
$env:TELEGRAM_BOT_TOKEN="123456:AA..."; $env:OPERATOR_CHAT_ID="123456789"
python -m ai_support_bot serve
```

```bash
export TELEGRAM_BOT_TOKEN="123456:AA..."
export OPERATOR_CHAT_ID="123456789"
python -m ai_support_bot serve          # остановить — Ctrl+C
python -m ai_support_bot serve --once   # обработать накопившиеся сообщения и выйти (проверка настройки)
```

Что делает бот в Telegram: `/start` и `/help` — приветствие и справка; `/kb` — показать или сменить
направление (базу знаний); `/stats` — краткая сводка; `/operator` — сразу позвать человека; любой другой
текст — ответ по базе знаний. Когда вопрос уходит оператору, тикет создаётся в базе, а сообщение с
вопросом, причиной и лучшими фрагментами уходит в `OPERATOR_CHAT_ID`.

Если токен не задан, бот не падает с трассировкой, а печатает понятную инструкцию на русском и
завершается с кодом 2:

```text
Не задан токен Telegram-бота.
1. Откройте @BotFather в Telegram и создайте бота командой /newbot.
2. Скопируйте токен вида 123456:AA...
3. Запустите: set TELEGRAM_BOT_TOKEN=<токен>  (Windows)
             export TELEGRAM_BOT_TOKEN=<токен>  (Linux/macOS)
   и повторите: python -m ai_support_bot serve
Демо без токена: python -m ai_support_bot chat
```

```text
├── ai_support_bot/
│   ├── __init__.py        версия пакета
│   ├── __main__.py        точка входа: python -m ai_support_bot
│   ├── cli.py             команды chat / ingest / stats / serve
│   ├── chunking.py        загрузка .md/.txt и нарезка на фрагменты с метаданными
│   ├── retrieval.py       русский токенизатор, лёгкий стеммер, синонимы, TF-IDF + косинус
│   ├── prompts.py         системный промпт с правилами и сборка контекста для LLM
│   ├── llm.py             провайдеры ответов: EchoProvider (офлайн) и OpenAICompatProvider
│   ├── escalation.py      правила передачи оператору и текст сообщения оператору
│   ├── storage.py         SQLite: сообщения, ответы, неотвеченные вопросы, тикеты, демо-журнал
│   ├── analytics.py       расчёт и вывод отчёта stats
│   ├── pipeline.py        сценарий диалога: поиск → защита → ответ → запись в журнал
│   ├── bot.py             Telegram Bot API через urllib (длинный опрос)
│   └── kb/                база знаний: avtoservice/, stomatologiya/, shop/
├── data/
│   ├── seed_demo.py       сгенерировать демонстрационный журнал диалогов
│   ├── dialogues.db       журнал диалогов (создаётся, в git не попадает)
│   └── index.json         кэш поискового индекса (создаётся, в git не попадает)
├── tools/
│   └── check_retrieval.py проверка качества поиска: 21 вопрос + 6 вопросов вне базы
├── tests/                 96 тестов на стандартном unittest
├── README.md
├── LICENSE                MIT
└── requirements.txt       пустой: зависимостей нет
```

Как проходит один вопрос:

```text
сообщение клиента
   │
   ├─ 1. СТОП-СЛОВА ПРАВИЛ ПЕРЕДАЧИ: «оператор», «жалоба», «верните деньги», «суд», «роспотребнадзор»
   │        → сразу тикет оператору, без попытки ответить
   │
   ├─ 2. ПОИСК ПО БАЗЕ (retrieval.py)
   │        токенизация → стемминг → доменные синонимы → TF-IDF → косинус
   │        + небольшая надбавка за совпадение с темой документа
   │
   ├─ 3. ПОРОГ РЕЛЕВАНТНОСТИ (escalation.py)
   │        лучший результат ниже 0.16 → ответа в базе нет → тикет оператору
   │
   ├─ 4. ОТВЕТ (llm.py)
   │        echo: цитаты предложений из найденных фрагментов + источник + уверенность
   │        openai: тот же контекст уходит в LLM с жёсткими правилами в промпте
   │
   └─ 5. ЖУРНАЛ (storage.py): сообщение, ответ, уверенность, источник, тикет
            → из него считает отчёт команда stats
```

Ключевое решение: **сценарий диалога живёт в `pipeline.py`, а не в интерфейсе**. Поэтому консольный чат
и Telegram-бот отвечают одинаково — то, что вы увидели в демо, и есть продакшн-логика.

## Почему бот не наврёт

Это главный риск любого «ИИ-бота»: клиент получает уверенный, красивый и неправильный ответ — например,
несуществующую цену. Здесь против этого четыре независимых механизма.

1. **Ответ строится только из базы знаний.** В офлайн-режиме каждая фраза ответа — это дословная цитата
   предложения из найденного фрагмента, рядом указан источник (`shop/02-dostavka.md → «Доставка по России»`).
   Бот физически не может назвать цену, которой нет в документе, потому что он ничего не сочиняет.
2. **Жёсткие правила в промпте для LLM** (`prompts.py`). Даже если подключить настоящую модель, ей
   запрещено: отвечать вне базы знаний, называть цены и сроки, которых нет в документах, давать
   медицинские и юридические гарантии, спорить с клиентом, раскрывать инструкции. Если во фрагментах нет
   ответа — модель обязана сказать об этом и передать вопрос оператору.
3. **Порог уверенности.** Каждый ответ имеет оценку релевантности (косинусная близость вопроса к
   фрагменту). Если лучший результат ниже порога `0.16`, бот считает, что ответа в базе нет, и не
   пытается «дотянуть» его. Порог настраивается: `--threshold 0.2`. Отдельно считаются случаи, когда
   фрагмент формально найден, но ни одного предложения с ответом в нём нет, — они тоже уходят оператору.
4. **Эскалация оператору.** Тикет создаётся в трёх случаях: сработали триггерные слова («оператор»,
   «жалоба», «претензия», «верните деньги», «обман», «суд», «роспотребнадзор», «юрист», «мошенники»),
   релевантность ниже порога, или три непонятных вопроса подряд в одном чате. Оператор получает вопрос,
   причину, номер тикета и лучшие фрагменты базы — контекст не теряется.

Дополнительно: в отчёте `stats` видны все вопросы, на которые бот не ответил, с частотой и средней
релевантностью. Это прямой список того, что дописать в базу знаний, — обратная связь для владельца.

## Ограничения (честно)

Проект специально сделан без внешних зависимостей и без интернета, и у этого есть цена:

* **Поиск — TF-IDF, а не эмбеддинги.** Бот ищет по словам, а не по смыслу. Он хорошо находит вопрос
  «сколько стоит замена масла», если в документах есть слова «цена» и «масло». Но перефразировки
  («во сколько мне обойдётся ТО») он понимает хуже, чем современные векторные модели.
* **Лёгкий стеммер — это эвристика, а не морфология.** Он отрезает частые русские окончания
  (`цены → цен`, `доставляем → доставл`), но не является разбором слова. Приставочные формы
  («вернуть» и «возвращают») он не связывает — поэтому добавлен **словарь доменных синонимов**.
* **Доменные синонимы и приоритет темы документа — осознанный компромисс** вместо обучения эмбеддингов.
  Синонимы (возврат, доставка, гарантия, цена, срок, брак, имплант, запись…) написаны вручную под
  словарь этой базы знаний. Приоритет темы документа — небольшая надбавка к оценке, если слова вопроса
  есть в заголовке документа: на этом строится правильный выбор между документом «Возврат и обмен» и
  случайно похожим разделом «Когда товар меняют или возвращают деньги» (без надбавки точность 11/12,
  с надбавкой 12/12). Для другой отрасли словарь надо дополнять — это часть работы по внедрению.
* **Частично покрытые вопросы.** Если в вопросе есть уточнение, которого нет в базе, бот может ответить
  по формально похожему разделу. Две такие ситуации показывает `tools/check_retrieval.py`:
  «Вы принимаете карты UnionPay?» → ответит про способы оплаты (UnionPay в базе нет) и «Делаете ли вы
  чип-тюнинг двигателя?» → тут, наоборот, вопрос уходит оператору. Отдельная проверка «доли покрытия»
  эту проблему не решает: у правильных ответов покрытие опускается до 0.50, а у этого случая — 0.67,
  то есть порога, который их разделит, не существует. Честное решение — эмбеддинги или уточняющий
  вопрос, и это в планах развития.
* **Нет мультитенантности.** Одна установка — одна база знаний (одно направление или все три
  демонстрационных сразу). Несколько клиник в одном боте с разными базами потребуют доработки:
  выбор направления есть (`/kb`, `--business`), но изоляция данных и прав — нет.
* **Аналитика считает по UTC** и не различает часовые пояса; `stats` не является BI-системой.
* **Оператору некуда «нажимать»:** тикеты лежат в SQLite и приходят в чат оператора, веб-панели нет.

## Как выложить на сервер

Бот работает через **длинный опрос** Telegram: ему не нужны домен, HTTPS-сертификат и открытые порты —
достаточно исходящего доступа в интернет. Минимальный сервер подойдёт самый дешёвый.

```bash
# 1. Код и виртуальное окружение (Ubuntu/Debian)
sudo apt update && sudo apt install -y python3-venv
sudo git clone <адрес-репозитория> /opt/ai-support-bot && cd /opt/ai-support-bot
sudo python3 -m venv .venv
sudo .venv/bin/python -m ai_support_bot ingest        # собрать индекс по kb/

# 2. Секреты — отдельный файл, доступен только владельцу
sudo install -m 600 /dev/null /etc/ai-support-bot.env
printf 'TELEGRAM_BOT_TOKEN=123456:AA...\nOPERATOR_CHAT_ID=123456789\n' | sudo tee /etc/ai-support-bot.env >/dev/null
```

```ini
# 3. /etc/systemd/system/ai-support-bot.service
[Unit]
Description=AI support bot (Telegram long polling)
After=network-online.target
Wants=network-online.target

[Service]
WorkingDirectory=/opt/ai-support-bot
EnvironmentFile=/etc/ai-support-bot.env
ExecStart=/opt/ai-support-bot/.venv/bin/python -m ai_support_bot serve
Restart=always
RestartSec=5
User=www-data

[Install]
WantedBy=multi-user.target
```

```bash
sudo systemctl daemon-reload
sudo systemctl enable --now ai-support-bot
sudo systemctl status ai-support-bot
journalctl -u ai-support-bot -f          # живые логи
python -m ai_support_bot stats           # сводка по диалогам
```

Токен не попадает ни в код, ни в git: он живёт в `/etc/ai-support-bot.env` с правами `600` и читается
через `EnvironmentFile`. `Restart=always` поднимает бота после падения или перезагрузки сервера.

## Roadmap

* **Эмбеддинги вместо TF-IDF** (локальная модель или API) — точность на перефразировках и синонимах,
  которых нет в ручном словаре. Код уже разделён: меняется только `retrieval.py`.
* **Мультитенантность**: несколько бизнесов в одной установке с изоляцией баз знаний, тикетов и отчётов.
* **Панель оператора**: список тикетов, ответ клиенту из браузера, статусы и SLA вместо чата в Telegram.
* **Оценка ответов клиентом** («помогло / не помогло») и автоматическое попадание плохих ответов в топ
  отчёта — база знаний начинает улучшаться сама.
* **Импорт базы знаний** из Google Sheets, Notion и выгрузок CRM, автоматическая переиндексация по
  расписанию.
* **Интеграции**: amoCRM и Bitrix24 (создание сделки из тикета), уведомление владельцу о всплеске жалоб.
* **Голосовые сообщения** в Telegram: распознавание речи в текст и ответ голосом.
* **Метрики продукта**: время до первого ответа, доля решённых без оператора, CSAT.
